# セキュリティと検証の記録

この記録はソースレビュー、実行したテスト、依存監査の結果です。正式なCodex Securityのスキャン成果物ではありません。本番公開の承認や全プラットフォームの実機認証を意味しません。

## Codex Securityの利用可否

[Codex Security security-scan SKILL.md](skill://Plugin_1e648473be9c8191a91ac3947151af55/security-scan/SKILL.md)を読み、通常スキャンの手順を確認しました。同スキルは “Start source review and launch scan workers only after preflight returns `ready`.” と定めています。

この環境にはCodex Securityの監査ランタイム、スキャン開始/登録ツール、必須の `scan-prologue.md` と `core-scan.md` が公開されておらず、preflightを `ready` にできませんでした。そのため正式スキャンを開始せず、スキャンID・seal・公式レポートを生成したとは扱っていません。代わりに、[セキュリティ設計](security-design.md)に示す実装境界をレビューし、以下のテストと依存監査を行いました。正式ランタイムが利用できる環境での独立監査は公開前の追加検証として残っています。

## 修正した依存問題

当初のquick-xml 0.38.4に、属性重複検査の二乗時間DoS (RUSTSEC-2026-0194) と名前空間宣言によるメモリ消費DoS (RUSTSEC-2026-0195) が報告されていました。直接依存を修正版0.41へ更新し、旧バージョンを解消して、解析・OPML・監査を再検証しました。

現在のRustSec検査は通ります。proc-macro-errorの保守終了通知 RUSTSEC-2024-0370 は、任意のLinuxネイティブ検証でGTKのビルドマクロから入る依存として、`deny.toml` に理由付きの個別例外を記録しています。Windows/macOS/iOSの配布対象はGTKをコンパイルしません。既知のランタイム脆弱性と、他の保守終了通知の失敗設定は維持しています。依存の複数バージョンと未使用のライセンス許可は監査上の警告として残っています。

これらを取得するまでは、公開準備がすべて完了したという判断は行いません。運用形態を個人用から複数ユーザーへ変える場合は、認証・権限・データ分離の実装と検証を追加してください。
