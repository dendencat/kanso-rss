# セキュリティ設計

対象は個人用の単一ライブラリです。サーバーの管理者、トークンを持つ端末、OSのアプリデータ領域を信頼します。インターネットからのAPIリクエスト、購読URL、DNS応答、リダイレクト、RSS/Atom本文、記事リンク、OPMLを信頼しない入力として扱います。

## 保護する性質

1. APIはデータ読取り・変更の前にBearerトークンを検証する。トークンは乱数生成し、サーバーではSHA-256を一定時間比較する。
2. フィード取得は公開HTTP(S)・80/443に限定する。DNS応答の全IPとリダイレクト各宛先を検証し、検証したIPを実際の接続先へ固定する。プロキシを使ってこの境界を迂回しない。
3. 記事のHTML、スクリプト、画像、iframeを画面のDOMへ挿入しない。本文をテキスト化し、タイトル・本文・フォルダ名はtextContentで表示する。記事リンクはユーザー操作時にHTTP(S)だけを開く。
4. XMLのDTD、過剰な本文サイズ・構造、OPMLの過剰な深さを拒否する。解析をblockingプールへ移し、ネットワーク・更新・認証済みAPIの同時実行を制限する。
5. SQLはパラメータ化し、FTS検索語は引用句へ変換する。記事状態を再取得で上書きしない。OPMLの一部だけを保存しない。
6. Webのトークンと記事内容をlocalStorage、Service Workerのキャッシュへ保存しない。ログアウト・接続変更時には旧セッションの応答で画面を再表示しない。
7. ネイティブのIPCは許可したAPIパス・HTTPメソッドに限定する。リモートAPIはHTTPS必須で、リダイレクトへトークンを渡さない。外部ページをアプリの権限付きWebViewへ遷移させない。
8. 配布には実際の依存バージョン、原著作権とライセンス全文を付属させる。脆弱性・ライセンス・取得元検査が失敗した成果物をリリースワークフローで進めない。

## 実装箇所

| 境界 | 実装 |
|---|---|
| 認証・本文サイズ・並列数・HTTPヘッダー | `crates/server/src/lib.rs` |
| URL・IP・DNS固定・リダイレクト・解析上限 | `crates/core/src/fetch.rs` |
| OPML DTD拒否・深さ・件数 | `crates/core/src/opml.rs` |
| トランザクション・索引・SQL・保存上限・バックアップ | `crates/core/src/store.rs` |
| テキスト表示・安全なリンク・セッション切替 | `web/app.js` |
| キャッシュ対象の固定 | `web/sw.js` |
| ネイティブのIPC・ナビゲーション・接続先 | `apps/native/src/lib.rs` / `tauri.conf.json` |
| TLS・コンテナ権限・永続化 | `deploy/` / `Dockerfile` |
| CI権限・署名・配布・SSHホスト鍵 | `.github/workflows/` |

## 運用上の境界

トークン保有者は購読削除を含む全操作を行えます。ユーザーごとの権限、MFA、OAuthログイン、テナント分離を提供する設計ではありません。複数ユーザー向けに広げる場合はこの境界を再設計します。トークンの漏洩時は管理者が交換してサーバーを再起動します。

SQLiteファイルはアプリ側で暗号化しません。OSのディスク暗号化・アクセス制御と暗号化バックアップを運用側で設定します。APIにはブラウザのCORS許可を追加していません。WebはAPIと同じオリジン、ネイティブ・CLIはRustからアクセスします。
